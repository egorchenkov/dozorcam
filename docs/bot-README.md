# cctv-bot — изолированный Telegram-интерфейс видеонаблюдения

Реализация архитектуры из
`docs/cctv-telegram-interface-architecture-2026-08-23.md`. Отдельный бот,
отдельная forum-группа, отдельный системный пользователь. Сервис
детерминированный: LLM-клиента, свободного текста и tool-call здесь нет и не
должно появиться — неизвестный текст получает подсказку `/menu` и никуда не
передаётся.

## Состав

- `config.py` — конфиг из окружения (его заполняет каталог `/etc/cctv`); неполное
  или небезопасное окружение (например `http://` на не-loopback адрес Bridge) не
  даёт стартовать.
- `state.py` — SQLite: `camera_id → message_thread_id`, непрозрачные токены
  кнопок с TTL, дедуп `event_id`, однократная выдача по `request_id`, подписки
  на движение. Адресов камер и учётных данных в состоянии нет.
- `bridge.py` — клиент CCTV Bridge API v1 (loopback http или mTLS); загрузка медиа только с
  хоста Bridge, с лимитом размера и сверкой SHA-256, временный файл удаляется
  в любом исходе.
- `events.py` — приёмник `POST /v1/events` на stdlib (loopback, либо mTLS с `CERT_REQUIRED`);
  разбор события отделён функцией `normalize_event`.
- `bot.py` — темы, паспорт с четырьмя кнопками, публикация кадров и клипов.
- `main.py` — сборка процесса и страж окружения `_forbid_foreign_secrets`.

## Установка

Бот — часть приложения `cctv` (свой venv, точка входа `cctv-bot`). Настройки —
общий каталог `/etc/cctv` (см. `README.md` в корне и `deploy/config.example.toml`):

```toml
# /etc/cctv/config.toml
[bot]
chat_id = -1001234567890            # forum-супергруппа «Видеонаблюдение»
allowed_user_ids = [123456789]      # числовые Telegram id владельцев
# owner_ids = [123456789]           # кому личкой об авариях (по умолчанию allowed_user_ids)

# /etc/cctv/secrets.toml (0600, в git не попадает)
[bot]
bot_token = "<токен BotFather>"
```

Мост и бот на одном узле говорят по `http://127.0.0.1` (мост — порт 8780,
приёмник событий бота — 8781), сертификаты не нужны; на не-loopback адрес без
TLS ни мост, ни бот не стартуют. Разнесённая установка — `internal_tls = true` в
`[common]` и mTLS-материал: `bridge_url = "https://…"`, `bridge_client_cert/key`,
`bridge_ca`, а приёмник событий — тройкой `events_cert/key/client_ca` целиком.

Бот должен быть администратором группы с правом управления темами.

## Уведомления владельцу

Аварии всего видеонаблюдения бот пишет владельцу в личку сам: мост не отвечает
два опроса сторожа подряд — «движок не отвечает», ожил — «снова отвечает».
Упавшую службу (в том числе самого бота) объявляет `cctv-notify` из
OnFailure-юнитов — тем же токеном. Личка доходит только тому, кто хоть раз
нажал у бота «Старт».

## Приёмка

```bash
.venv/bin/python -m pytest -q
```

`tests/test_acceptance.py` проверяет изоляцию юнита, отсутствие LLM и доступа к
камерам в коде бота, отсутствие внешних привязок в дереве и отказ старта на
неполном или небезопасном окружении; `tests/test_internal_link.py` — живую связь
мост↔бот по loopback и по mTLS. Живые проверки (камера, группа) — на стенде.

## Что нужно

- Linux amd64 или arm64 от 2 ГБ RAM (сколько под ваши камеры — [sizing.ru.md](sizing.ru.md)
  и калькулятор на [сайте](https://egorchenkov.github.io/dozorcam/ru/#sizing)); 32-битный ARM
  (armv7) не поддерживается.
- Docker с плагином compose — установщик предложит поставить.
- Доступ к `api.telegram.org`; IP-камеры в сети, до которой узел достаёт.
- Токен бота: [@BotFather](https://t.me/BotFather) → `/newbot`.

## Установка одной командой

```bash
curl -fsSL https://egorchenkov.github.io/dozorcam/install.sh | sh
```

Что делает, по порядку (POSIX sh — можно прочитать до запуска):

1. Проверяет Docker и плагин compose; без них предлагает официальный скрипт `get.docker.com`
   (y/N).
2. Скачивает `compose.yml`, `.env.example`, `CHANGELOG.md` и обёртку `dozorcam` последнего
   релиза в `~/dozorcam` (git не нужен) и сверяет их с `SHA256SUMS` релиза.
3. Спрашивает токен бота и проверяет его в Telegram (`getMe`).
4. Язык берёт из `$LANG` (`CCTV_LANG`), часовой пояс — с хоста (`CCTV_TZ`).
5. Подбирает буфер видео в RAM по памяти машины: 25 % RAM в пределах 512 МБ–4 ГБ;
   предупреждает, если RAM меньше 2 ГБ.
6. Закрепляет образ по digest, запускает, ждёт healthcheck и печатает ссылку владельца
   `https://t.me/<бот>?start=<код>` с QR-кодом.

Повторный запуск в том же каталоге сохраняет `.env` (токен, настройки). Установка без
вопросов — всё переменными:

| Переменная | Что |
|---|---|
| `DOZORCAM_TOKEN` | токен бота |
| `DOZORCAM_LANG` | `en` или `ru` |
| `DOZORCAM_TZ` | пояс IANA, например `Europe/Moscow` |
| `DOZORCAM_DIR` | каталог установки, по умолчанию `~/dozorcam` |
| `DOZORCAM_VERSION` | релиз, по умолчанию последний |
| `DOZORCAM_INSTALL_DOCKER=1` | поставить Docker без вопроса |

```bash
curl -fsSL https://egorchenkov.github.io/dozorcam/install.sh | DOZORCAM_TOKEN=<токен> DOZORCAM_TZ=Europe/Moscow sh
```

## Первые 10 минут

1. **Владелец.** Откройте ссылку, которую напечатал установщик (или отсканируйте QR), и
   нажмите «Старт» — вы владелец. Ссылка потерялась: `~/dozorcam/dozorcam code`.
2. **Куда присылать события.** Бот спрашивает «Куда присылать события камер?» и закрепляет
   прогресс «Шаг 1/3 · 2/3 · 3/3».
   - «📱 Сюда, в этот чат» — готово одним нажатием; хватит на 1–3 камеры.
   - «👥 В группу с темами» — создайте группу, включите «Темы», добавьте бота админом с правами
     «Управление темами», «Удаление сообщений» и «Закрепление сообщений». Кнопки Android /
     iPhone / Компьютер показывают, где каждый шаг в вашем клиенте; готовую группу бот заметит
     сам в течение минуты (`/setup` — сразу). Он создаст тему «Пульт» с картой камер.
   - Группу можно подключить и позже командой `/mode`; ничего не потеряется.
3. **Первая камера.** `/add` — бот ищет в сетях узла и через WS-Discovery. Нажмите камеру,
   пришлите `логин пароль` одним сообщением (оно сразу удаляется), дайте имя. Камера без
   ONVIF: `/add <IP>` (пробуются типовые пути RTSP) или `/add rtsp://хост:порт/путь`. Ничего не
   нашлось — бот скажет, где искал; добавьте `CCTV_DISCOVERY_NETWORKS` в `.env` и
   `dozorcam restart`.
4. **Первый кадр.** Он приходит туда, куда идут события; камера появляется на карте. Нажмите
   её — карточка: 📷 Кадр, 🎞 Клип 30 с.
5. **Детекция людей.** Посмотрите на сцену и включите детекцию в ⚙️ Настройке карточки.
   Пройдите перед камерой — придёт снимок с рамкой и под ним «🎞 Клип вокруг кадра». `/help`
   покажет всё для вашего режима.

## Установка вручную через docker compose

```bash
git clone https://github.com/egorchenkov/dozorcam.git && cd dozorcam
cp .env.example .env && sed -i 's/^CCTV_BOT_TOKEN=.*/CCTV_BOT_TOKEN=<токен>/' .env
docker compose pull --ignore-pull-failures && docker compose up -d
docker compose logs bot | grep SETUP     # одноразовый код: пришлите боту /start <код>
```

В `.env` задайте `CCTV_IMAGE_TAG` на релиз (например `CCTV_IMAGE_TAG=0.3.0`), `CCTV_LANG` и
`CCTV_TZ`. Если реестр недоступен, compose соберёт тот же образ локально из `Dockerfile`.
Обёртка `dozorcam` работает и здесь: `scripts/dozorcam` должна лежать рядом с `compose.yml`
и `.env` (скопируйте её туда).

## Обёртка dozorcam

```
dozorcam status | logs [-f] [engine|bot] | code | restart | start
dozorcam update [-y] [ВЕРСИЯ] | backup [ФАЙЛ] | restore [-y] ФАЙЛ
dozorcam uninstall [-y] [--volumes] [--image]
```

`restart` пересоздаёт контейнеры с текущим `.env` — после правки `.env` нужен он.

## Обновление

```bash
~/dozorcam/dozorcam update
```

Берёт последний релиз из GitHub Releases, показывает изменения между вашей версией и им,
обновляет `compose.yml` и образ, закреплённый по digest, запускает и ждёт healthcheck. Если
проверка не прошла, возвращаются прежние `.env` и `compose.yml` и снова запускается прежний
образ (он остаётся на машине — откату сеть не нужна). `update 0.3.0` — конкретная версия,
`-y` — без вопросов. Бот раз в сутки показывает «⬆️ Доступна X» на карте камер и в `/version`
(`CCTV_UPDATE_CHECK=0` — выключить).

## Резервная копия и восстановление

```bash
~/dozorcam/dozorcam backup        # ~/dozorcam/backups/dozorcam-<дата>-<время>.tar.gz
~/dozorcam/dozorcam restore ~/dozorcam/backups/dozorcam-<дата>-<время>.tar.gz
```

Один tar.gz: `.env` (с токеном бота — храните файл в закрытом месте), `compose.yml`,
`config/`, тома состояния движка и бота (реестр камер с паролями, владелец, группа, карта).
На время копии контейнеры приостанавливаются и запускаются снова. Буфера видео в копии нет:
он живёт в RAM. На другой машине: запустите установщик, затем там же `restore`.

## Удаление

```bash
~/dozorcam/dozorcam uninstall                      # отдельно спросит про состояние и образ
~/dozorcam/dozorcam uninstall -y --volumes --image  # всё, без вопросов
```

Тома состояния (список камер, пароли камер, владелец) и образ удаляются, только если вы
согласитесь; `~/dozorcam` с `.env`, `config/` и `backups/` остаётся — удалите сами, если не
нужен.

## Переход с 0.1.x

- В 0.1.x обёртки `dozorcam` нет: скачайте `dozorcam` из файлов
  [последнего релиза](https://github.com/egorchenkov/dozorcam/releases/latest) рядом с
  `compose.yml` и `.env`, `chmod +x dozorcam`, затем `./dozorcam update`. В git-копии можно и
  так: `git pull && docker compose pull && docker compose up -d`.
- Режим доставки остаётся «тема на камеру»; темы и панели переиспользуются, в теме «Пульт»
  вместо прежней панели появляется карта камер.
- До 0.3.0 время всегда было московским; теперь оно по `CCTV_TZ`, без него — UTC. В Москве:
  `CCTV_TZ=Europe/Moscow`. Ключа `diag_utc_offset` больше нет.
- Боту в группе нужно право «Закрепление сообщений»; если его нет, бот скажет.

## Режимы доставки

Куда идут события камеры — это *маршрут*. Пресетов три; владелец меняет их командой `/mode`
(или «🔀 Куда идут события» на карте). Камеры, их id и история остаются; темы
переиспользуются; прежняя карта говорит, куда переехала. Если Telegram отказал (права,
темы), остаётся прежний режим.

| Пресет | Куда идут события | Кому подходит |
|---|---|---|
| Один чат без тем (`flat`) | в саму группу, а без группы — в личку каждому допущенному | 1–3 камеры, самый быстрый старт |
| Тема на камеру (`camera`, до 0.3.0 — единственный) | у каждой камеры своя тема с закреплённой карточкой | от 4 камер |
| Тема на локацию (`location`) | темы «Дом», «Дача», внутри события нескольких камер с хэштегами | несколько мест |

- **Мастер.** После кода владельца бот спрашивает «Куда присылать события камер?»:
  «📱 Сюда, в этот чат» — настройка за одно нажатие (плоский режим в личке, карта закреплена
  там же, `/add` работает прямо там); «👥 В группу с темами» — ждёт группу. От 4 камер мастер
  советует темы. Закреплённое сообщение-прогресс «Шаг 1/3 владелец · 2/3 куда присылать
  события · 3/3 первая камера» правится по ходу и в конце открепляется.
- **Проверка группы.** Группе с темами нужен бот-администратор с правами «Управление темами»,
  «Удаление сообщений» и «Закрепление сообщений»; плоской группе — двумя последними. Бот сам
  перепроверяет группу при каждом повышении, при переезде в супергруппу и раз в минуту в
  течение суток после сообщения о недостачах (о включении тем Telegram боту не сообщает);
  `/setup` — проверить сейчас. Кнопки Android / iPhone / Компьютер показывают, где каждый шаг в
  этом клиенте.
- **Локация.** 📍 Локация на карточке задаёт камере тег `location`; без него берётся
  площадка реестра (если она не совпадает с именем камеры), иначе — тема «Камеры». Своя тема
  у камеры может остаться в любом режиме.
- **Хэштеги.** Подпись каждого события кончается хэштегами камеры и локации
  (`#калитка #дача`): нажатие — и Telegram фильтрует чат по камере или месту.
- **Склейка.** События камеры за 60 с правят её предыдущий пост — свежий кадр и «+N за минуту ·
  последнее 13:01:40»; кнопка клипа — вокруг свежего кадра. Окно считается от первого поста:
  у камеры, которая видит людей постоянно, — один пост в минуту. `CCTV_EVENT_MERGE_SEC`
  (`event_merge_sec`), `0` — каждое событие отдельно.
- **Запрошенные кадр и клип** приходят тому, кто просил; звук — по своей подписке
  каждого (🔔 на карточке).

## Карта камер и карточка камеры

Одно закреплённое сообщение на место: тема «Пульт», сама группа в плоском режиме или личка
каждого допущенного без группы. На карте — «📍 Камер: 4 · в сети: 4 · событий сегодня: 12»,
камеры по секциям локаций, 🔕 у камер без уведомлений, кнопка на камеру, ➕ Добавить камеру,
🧠 Модель детектора, 🎯 Пороги, 🔀 Куда идут события и строка «⬆️ Доступна X», если вышла
новая версия. Больше 12 камер в нескольких локациях — кнопки по страницам локаций.

Нажмите камеру — то же сообщение станет её **карточкой**: статус, локация и хэштеги,
📷 Кадр, 🎞 Клип 30 с, 🔄 Статус, 🔔 уведомления, ⏸ Пауза, ✏️ Имя, 📍 Локация,
⚙️ Настройка, 🗑 Снять и «◀ К карте»; забытая карточка через 10 минут снова становится
картой. Закреплённая панель темы камеры — та же карточка. `/cam <имя>` присылает карточку
сообщением (по имени, `#хэштегу` или id камеры; в теме камеры без имени — эту камеру).

Новая камера стартует с **выключенной** детекцией людей: посмотрите на сцену и включите её в
⚙️ Настройке. Под каждым событием — «🎞 Клип вокруг кадра»: клип вырезается из буфера вокруг
момента, когда был замечен человек, даже если детектор отставал на несколько секунд; ответ на
снимок события любым текстом делает то же.

## Команды и кнопки

| Команда | Что делает |
|---|---|
| `/start <код>` | один раз, в личке: делает вас владельцем (или ссылка `t.me/<бот>?start=<код>`) |
| `/add` | ищет камеры; `/add <IP>`, `/add rtsp://хост:порт/путь [rtsp://… поток детектора]` |
| `/menu` | список камер; в теме камеры — её кнопки |
| `/cam <имя>` | карточка камеры здесь |
| `/mode [camera\|location\|flat]` | куда идут события (владелец) |
| `/invite` | одноразовая ссылка для ещё одного человека на сутки и список со «Снять» (владелец, в личке) |
| `/setup` | перепроверяет группу, подсказывает, какого права не хватает |
| `/model` | модель и файл детектора людей, смена на ходу с автооткатом |
| `/lang en\|ru` | язык интерфейса; по умолчанию `CCTV_LANG`, иначе язык Telegram владельца, иначе английский |
| `/help` | команды и кнопки текущего режима |
| `/version` | установленная версия и последний релиз |

## Люди: владелец, допущенные, приглашённые

Владелец — тот, кто первым прислал код установки (`dozorcam code` показывает его снова,
пока владельца нет). Допущенные — владелец, `CCTV_ALLOWED_USER_IDS` и приглашённые через
`/invite`; команды и кнопки отвечают только им. В режиме с группой ленту видят все участники
группы; без группы каждый допущенный получает события в личку — со своей картой и своими
уведомлениями. `CCTV_CHAT_ID` / `CCTV_ALLOWED_USER_IDS`, если заданы, сильнее мастера (кода
тогда нет). `CCTV_OWNER_IDS` — кому слать аварии в личку (по умолчанию — допущенным).

## Камеры

| Что | Как |
|---|---|
| ONVIF (Profile S) | поиск в собственных /24 узла и через WS-Discovery (или `CCTV_DISCOVERY_NETWORKS`); потоки и снимок — через ONVIF Media |
| Любая RTSP-камера | `/add rtsp://хост:порт/путь`, снимок берётся из потока |
| По IP и логину, без ONVIF | `/add <IP>`: типовые пути Reolink, TP-Link Tapo/VIGI, Uniview, Axis, Xiongmai/XMEye и общие, по 3 с на путь, сначала узнанная марка; бот показывает, какой сработал, и отдаёт детектору второй поток — [cameras.ru.md](cameras.ru.md) |
| Hikvision (ISAPI) | шаблоны RTSP и `/ISAPI/Streaming/channels/101/picture`, где ONVIF молчит; гейт по людям от камеры (ONVIF FieldDetector, `human_gate_mode`) |

Логин и пароль присылаются одним сообщением `логин пароль`; бот удаляет его до обращения к
движку и не принимает пароль внутри адреса. Пустой поиск говорит, где искал: другие подсети —
в `CCTV_DISCOVERY_NETWORKS`, или введите адрес (✍️).

Новую неактивированную Hikvision активирует сам `/add`: поиск помечает её «🔐», бот просит
слово подтверждения, затем пароль администратора (или генерирует его), а движок активирует
камеру (ISAPI-активация V3 или прежний протокол с challenge), проверяет пароль одним входом,
включает ONVIF с отдельным ONVIF-пользователем, проверяет поток и заводит камеру;
«Активировать все» — то же для всех найденных новых. Пароль показывается владельцу один раз, в
личке; копия — в состоянии движка (`activation-vault.json`, 0600). Камеры других
производителей нужно заранее активировать их средствами.

## Детектор людей

| Семейство | Файл по умолчанию | Стартовый порог | Лицензия весов | В образе |
|---|---|---|---|---|
| YOLOX (по умолчанию) | `yolox_tiny.onnx` | 0.30 | Apache-2.0 (Megvii) | да |
| YOLOv5 | `yolov5n.onnx` | 0.35 | AGPL-3.0 (Ultralytics) | нет — скачиваете сами |
| YOLOv8-стиль (YOLOv8, YOLO11) | `yolov8n.onnx` | 0.30 | AGPL-3.0 (Ultralytics) | нет — скачиваете сами |

- Веса под AGPL-3.0 проект не распространяет: если вы положили файлы YOLOv5/YOLOv8 в
  `config/models/` (читаемыми для uid 10001), их лицензия действует для вашей установки. По
  шагам: [models.md](models.md#where-to-put-your-own-weights). Выбор — `/model` или
  `person_model_family` / `person_model` в `config.toml`.
- **Порог по камере.** После смены модели и по «🔄 Откалибровать» (🎯 Пороги на карте) движок
  набирает ~600 кадров фона на камеру и ставит порог = 99-й перцентиль оценки фона + 0.10, но
  не ниже стартового порога модели. Подтверждённые проходы (2 кадра подряд и/или сигнал
  человека от самой камеры по ONVIF) ограничивают его сверху. Ручной порог сильнее
  автоматического, переживает перезапуск и перестаёт действовать при смене модели.
- **Подтверждение от камеры.** Камеры со своим распознаванием людей могут отсекать кадры
  детектора или подтверждать человека (`human_gate_mode = "confirm"`); `human_quiet_cameras`
  разрешает камере доверять своему молчанию. Рамка сверяется с тем же местом кадра несколько
  секунд назад: то, что не двигается, — не человек.
- **Честное ограничение:** автокалибровка находит порог *над шумом*; сколько людей
  пропущено, она не измеряет. Если камера пропускает проходы, задайте порог вручную.
- **Диагностика.** Движок пишет в журнал отвергнутых кандидатов с причиной и суточную сводку
  возможных пропусков (`python -m cctv diag-summary`).

## Настройки

Большинству установок хватает `.env` рядом с `compose.yml` (образец — `.env.example`).
Расширенные настройки — в каталоге конфига (`CCTV_CONFIG_PATH`, по умолчанию `./config`,
монтируется только на чтение): `config.toml` с разделами `[common]`, `[engine]`, `[bot]`,
`cameras.json`, `secrets.toml` — см. `deploy/config.example.toml`. Ключ `foo` становится
`CCTV_FOO`; окружение сильнее файла; процесс видит только `[common]` и свой раздел. После
правки `.env` — `dozorcam restart` (пересоздаёт контейнеры).

| Переменная | По умолчанию | Что |
|---|---|---|
| `CCTV_BOT_TOKEN` | — | токен бота (установщик спросит и проверит) |
| `CCTV_LANG` | язык Telegram владельца, иначе `en` | язык всей установки: бот, сводка, healthcheck |
| `CCTV_TZ` | UTC (карта предупреждает) | пояс IANA для подписей и суток сводки |
| `CCTV_EVENT_MERGE_SEC` | `60` | окно склейки событий камеры; `0` — выкл. |
| `CCTV_UPDATE_CHECK` | вкл. | `0` — не спрашивать GitHub Releases о новой версии |
| `CCTV_DISCOVERY_NETWORKS` | собственные /24 | где искать `/add`, например `192.0.2.0/24,198.51.100.0/24` |
| `CCTV_CHAT_ID`, `CCTV_ALLOWED_USER_IDS`, `CCTV_OWNER_IDS` | мастер | группа и люди вручную вместо мастера |
| `CCTV_TELEGRAM_API` | `api.telegram.org` | свой сервер Bot API |
| `CCTV_BUFFER_TMPFS` | установщик: 25 % RAM, 512 МБ–4 ГБ | RAM под буфер видео всех камер |
| `CCTV_BUFFER_MAX_BYTES` | 400 МиБ, установщик: 200 МиБ | лимит буфера на поток (основной и детекторный); все камеры обязаны поместиться в `CCTV_BUFFER_TMPFS` — общего лимита у движка нет |
| `CCTV_SPOOL_TMPFS`, `CCTV_STORAGE_BUDGET_BYTES` | 512m, буфер + транзит | транзит движка и бюджет хранилища |
| `CCTV_BRIDGE_PORT`, `CCTV_EVENTS_PORT`, `CCTV_RTSP_PROXY_PORT` | 8780, 8781, 28554 | порты хоста; второй установке рядом — другие |
| `CCTV_IMAGE`, `CCTV_IMAGE_TAG` | `ghcr.io/egorchenkov/dozorcam`, закреплён по digest | образ |

| Путь в контейнере | Что | Переменная |
|---|---|---|
| `/etc/cctv` (только чтение) | `config.toml`, `cameras.json`, `secrets.toml`, `models/` | `CCTV_CONFIG_DIR` |
| `/var/lib/cctv/state` (тома `engine-state`, `bot-state`) | килобайты: реестр камер, пульс детектора, SQLite бота | `CCTV_STATE_DIR` |
| `/var/lib/cctv/buffer` (tmpfs) | 10 минут сегментов на поток | `CCTV_BUFFER_DIR` |

Реестр, заведённый из чата, движок пишет в `state/cameras.json`; `cameras.json` каталога
конфига — только исходник для пустого состояния. Правка каталога конфига перезапускает
цепочку внутри контейнера. Без токена или с отклонённым Telegram токеном бот ждёт правки:
`docker compose ps` покажет unhealthy, причина — в `dozorcam logs bot`.

## Сеть

Оба контейнера работают в сети хоста: движку нужен multicast WS-Discovery и прямой RTSP к
камерам, а мост↔бот без TLS разрешены только по loopback. Цена — нет сетевой изоляции
контейнера: процессы видят все интерфейсы узла и могут ходить куда угодно. Остальное ужато
(non-root uid 10001, корневая ФС только на чтение, `cap_drop: ALL`, `no-new-privileges`), но
если узел смотрит в недоверенные сети — ограничьте исходящий трафик файрволом хоста. Камеры
лучше держать в отдельном VLAN без выхода в интернет. Исходящие запросы: `api.telegram.org`
(или `CCTV_TELEGRAM_API`) и раз в сутки `api.github.com` за последним релизом.

## Связь движок ↔ бот и TLS

Движок и бот говорят по loopback (`127.0.0.1:8780` мост, `:8781` приёмник событий бота);
не-loopback адрес без TLS — отказ старта. Для разнесённой установки — `CCTV_INTERNAL_TLS=1`
(`internal_tls = true` в `[common]`): mTLS в обе стороны.

## Структура

```
cctv/engine/   мост (HTTP API), конвейер (буфер записи, гейт движения, детектор людей YOLO,
               фильтр неподвижных), RTSP-прокси с паролями, провижн, поиск камер ONVIF
cctv/bot/      Telegram-интерфейс (python-telegram-bot): маршруты (режимы доставки), карта, карточки, мастер
cctv/i18n/     locales/<lang>.json — всё, что читает человек; CI сверяет паритет en/ru
cctv/container супервизор контейнера (роль engine | bot) и его healthcheck
scripts/       install.sh, обёртка dozorcam, release-assets.sh, site-sync.py, sizing-bench.sh
deploy/        config.example.toml, secrets.example.toml, systemd-юниты (справочно, без контейнера)
tests/         pytest: движок, бот во всех режимах доставки, i18n-гейт, smoke-тест установщика
```

## Разработка

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt && .venv/bin/pip install -e . --no-deps
.venv/bin/python -m pytest -q
```

Контрактным тестам нужны `ffmpeg`, `openssl` и `curl`, без них они пропускаются. Сборка
multi-arch без QEMU: `docker buildx build --platform linux/arm64,linux/amd64 -t dozorcam:dev .`
(нужен containerd image store — по умолчанию с Docker 29 — или `--output type=oci`). Всё, что
читает человек, идёт через `cctv/i18n/locales` (en и ru); CI падает на русских литералах в
коде. `scripts/site-sync.py --check` держит версию на сайте и в обоих README равной релизу.

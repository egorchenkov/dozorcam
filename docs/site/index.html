Your cameras, your Telegram, no cloud

Dozorcam watches IP cameras on your own Linux box, finds people and sends snapshots and clips to a Telegram forum group — one topic per camera, plus a “Control” topic for the whole system.

InstallSource on GitHub

What it does

Recording buffer in RAMA rolling buffer per camera on tmpfs: the moments around an event are there, and the SD card or disk is not worn out.
People, not leavesMotion gate with a per-camera noise floor, then an ONNX person detector (YOLOX-Tiny by default) and a filter for objects that never move.
Telegram as the interfaceSnapshots and clips on detection and on demand, pause, rename, retire a camera — all with buttons in the camera topic.
Setup from the chatA one-time code in the logs makes you the owner; the bot creates its topics and finds cameras over ONVIF / WS-Discovery.
Models and thresholdsYOLOX, YOLOv5 or YOLOv8-style models, switched on the fly from the bot; per-camera threshold auto-calibrated against the scene noise.
Small and locked downOne multi-arch image (amd64, arm64) for engine and bot: non-root, read-only root filesystem, no capabilities, healthchecks.

Install in 3 steps

You need Linux (amd64 or arm64) with Docker and the compose plugin, and the node must reach api.telegram.org.

  1. Create a bot. In Telegram open @BotFather, send /newbot and copy the token.
  2. Start Dozorcam with the token: 
    git clone https://github.com/egorchenkov/dozorcam.git && cd dozorcam
cp .env.example .env && sed -i 's/^CCTV_BOT_TOKEN=.*/CCTV_BOT_TOKEN=<token>/' .env
docker compose pull --ignore-pull-failures && docker compose up -d
    The release image is ghcr.io/egorchenkov/dozorcam; if it cannot be pulled, compose builds it locally.
  3. Claim the bot. docker compose logs bot | grep SETUP prints a one-time code — send /start <code> to the bot in a private chat. Then create a group with Topics enabled, add the bot as an admin (“Manage topics”, “Delete messages”) and send /add to connect cameras.

Supported cameras

KindHow it is connected
ONVIF (Profile S)Found automatically (local /24 networks and WS-Discovery); stream and snapshot URIs come from ONVIF Media.
Any RTSP camera/add rtsp://host:port/path; the snapshot is taken from the stream.
Hikvision (ISAPI)Built-in RTSP and /ISAPI/Streaming/channels/101/picture templates where ONVIF is silent; optional person gate from the camera's own analytics.

Tested live on Hikvision G0/G2/G5 and Tantos cameras. Cameras must be activated with the vendor's tools first. Other vendors should work over ONVIF/RTSP but are untested.

How it looks

# Yard · camera topic

👤 Person detected · Yard · 14:02:19

🎞 Clip around this frame📷 Frame🎞 Clip 30 s🔄 Status

Every camera gets its own topic. A detection arrives as a snapshot with the box drawn by the detector; the buttons below build a clip around that moment from the buffer, take a fresh frame or show the camera status.

The “Control” topic carries the system status, the detector model menu (/model) and per-camera thresholds.

The pictures on this page are illustrations: a drawn scene and the bot's real button labels. No footage from real cameras is published here.

Languages

The bot speaks English and Russian and follows your Telegram language (/lang en|ru to change). More languages are planned.

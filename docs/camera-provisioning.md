# Заведение камер из чата (Ф4)

Добавление, правка и удаление камеры делаются кнопками на пульте и в теме камеры.
Реестр `/etc/cctv-bridge/cameras.json` по-прежнему принадлежит root: граница не
снята, а перенесена в один маленький привилегированный процесс.

## Кто что делает

- **Бот** (`cctvbot`) — только диалог: кнопки, ввод, удаление сообщения с паролем.
- **Мост** (`cctv`) — опрос сети, ONVIF, проверка потока, хранение «пробы» в памяти.
- **Писарь** (`cctv-provision.service`, root) — единственный, кто пишет реестр и
  перезапускает цепочку. Вход — unix-сокет `/run/cctv-provision.sock` (root:cctv
  0660) с проверкой клиента по SO_PEERCRED; команды `list`, `upsert`, `delete`.

## Путь пароля

1. Человек присылает «логин пароль» в тему пульта.
2. Бот **удаляет сообщение до любого сетевого вызова** (`deleteMessage`) — группа
   индексируется в личный RAG, и лишней секунды ей хватило бы.
3. Пароль уходит одним POST `/v1/discovery/probes` на мост и остаётся там в памяти
   под непрозрачным токеном (TTL 15 минут). Обратно приходит только токен и сводка
   с затёртым userinfo (`rtsp://***@…`).
4. Заведение камеры отправляет токен, а не пароль. В реестр пароль кладёт писарь.

Ни в один LLM пароль не попадает: у `cctv-tg-bot` нет ни модели, ни прокси
(`_forbid_foreign_secrets` роняет старт при чужих ключах в окружении), а сообщение
из чата исчезает раньше, чем его успевает увидеть выгрузка.

## Поиск камер

`CCTV_DISCOVERY_NETWORKS` в `/etc/cctv-bridge/bridge.env` — сейчас
`192.0.2.0/24,198.51.100.0/24`. Опрос: TCP-развёртка портов 554/80/8000/8899/8080,
затем unicast-ONVIF (`GetSystemDateAndTime` без авторизации) и баннер RTSP OPTIONS.
Мультикаст WS-Discovery не используется: камеры за WireGuard, мультикаст туда не
доходит. Сети принимаются только приватные и суммарно не больше 4096 адресов.

Параметры камеры определяются по ONVIF (`GetProfiles` → `GetStreamUri` →
`GetSnapshotUri`, выбор основного потока по разрешению, детекторного — по
наименьшему), при молчании ONVIF — по типовым адресам вендора с проверкой
DESCRIBE. Адрес из ответа камеры переписывается на тот, по которому мост до неё
дошёл: устройства часто отдают свой внутренний IP.

## Что доступно в чате

- Пульт: «➕ Добавить камеру» → список найденных → логин/пароль → имя. `camera_id`
  собирается транслитерацией имени, столкновение разрешается суффиксом.
- Тема камеры: «⚙️ Настройка» — карточка реестра без пароля и кнопки «🔑 Логин и
  пароль» (перепроверка и обновление потоков), «👤 Детекция людей», «❌ Удалить из
  реестра» (подтверждение словом «удалить»).
- Новая камера заводится **без** детекции людей: сцену сперва смотрят глазами.

Любая запись в реестр перезапускает `cctv-rtsp-proxy → cctv-bridge → cctv-pipeline`
(писарь делает это после ответа в чат, с задержкой 2 с), бот сверяет темы через
25 с. Каждое изменение оставляет копию в `/etc/cctv-bridge/backups/`.

## Иконки тем

Иконка выбирается по площадке, а не по `camera_id`: `дач` → 🏠 (дача),
`город` → 🏛 (город), остальное — 👀. Новые камеры дачи получат иконку
дачи сами.
